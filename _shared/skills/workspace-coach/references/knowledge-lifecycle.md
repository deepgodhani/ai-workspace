# Knowledge Lifecycle

Use this progression:

`capture → verify → distill → promote → index → commit`

Unverified candidates belong in `knowledge/inbox/`. Promote only conclusions
that are reusable beyond one project and have sufficient evidence. Every
durable note should state scope, status, verification date, evidence,
exceptions, and a review date when version-sensitive.

Do not promote complete reports or raw crawls. Project-specific observations
remain in the project or become clearly labeled case studies.
